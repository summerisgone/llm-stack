# PAT-сервис

[English](pat-service.md) | [Оглавление справочника](README.ru.md)

`pat-service` - собственный Go-сервис стека. Он превращает персональный токен
доступа (`sk-...`) в проверенную идентичность, помечает каждый запрос к модели
сессией и полосой приоритета, проксирует вызовы MCP-инструментов и отдаёт
дашборд самообслуживания. Он сознательно **ничего не планирует**: очередь и
справедливость принадлежат llm-d EPP.

## Что делает

1. **Аутентифицирует программы.** PAT ищется по HMAC-хэшу (`PAT_HASH_KEY`);
   отозванный или истёкший токен отклоняется со следующего же запроса.
   Идентичностью становится владелец (Keycloak `sub` и имя пользователя).
2. **Подменяет учётные данные.** Запрос идёт дальше в приватный AI Gateway с
   собственным client-credentials JWT pat-service (клиент Keycloak
   `pat-gateway`), а не с PAT. Заголовки идентичности от клиента сначала
   срезаются и заменяются доверенными.
3. **Склеивает сессии.** По истории сообщений вычисляется стабильный ключ
   сессии, так что все шаги одного запуска агента получают один
   `X-Session-Key` (сессия в Langfuse, "прогретость" в EPP).
4. **Ставит метку приоритета.** Выбирает полосу EPP (`warm`, `normal`,
   `demoted`) и fairness id (`sub` владельца) и отправляет их заголовками.
5. **Учитывает использование.** Токены и стоимость каждого запроса идут в
   счётчики Prometheus и в таблицу `qos_events`, которую читает дашборд.
6. **Проксирует MCP.** `/mcp/<name>/` аутентифицирует вызывающего,
   ограничивает частоту вызовов инструментов и передаёт запрос MCP-серверу
   с заголовками идентичности ([MCP](mcp/README.ru.md)).
7. **Выпускает ключи агентов.** `/api/agent-token` создаёт короткоживущий PAT
   для агентов пользователя и кладёт его туда, откуда его читают их поды
   ([агенты](agents/README.ru.md#токены)).

## Чего не делает

Эта граница решена окончательно
([архитектура](../architecture/README.md#queueing-and-fairness-who-owns-what),
[ADR 0008](../adr/0008-per-user-fair-share.md)); не стройте в обход неё.

- **Нет очереди, нет лимитера инференса, нет решений о допуске.** Каждый
  авторизованный запрос к модели проксируется сразу. Если запросу надо
  подождать, его придерживает EPP.
- **Нет rate limit-а на пользователя для `/v1`.** Это `BackendTrafficPolicy`
  AI Gateway по `X-User-Id`. Единственный лимитер pat-service - для вызовов
  MCP-инструментов.
- **Месячный бюджет не применяется.** `QOS_MONTHLY_LIMIT` только
  показывается на дашборде.
- **Трафик чата Open WebUI сервис не видит.** Open WebUI ходит в шлюз
  напрямую, поэтому у браузерных чатов нет ни ключа сессии, ни полосы. Это
  одна из причин, почему планировщик здесь был бы ошибкой: он распределял бы
  только часть нагрузки.
- **Промпты и ответы не хранит.** Они в Langfuse.
- **Не является провайдером идентичности.** Пользователи, роли и пароли - в
  Keycloak; сам дашборд тоже входит через Keycloak (клиент `pat-dashboard`).

## Эндпоинты

| Путь | Кто вызывает | Что делает |
| --- | --- | --- |
| `/platform/` (публичный, префикс срезается) -> `/` | браузер | дашборд: создание, список и отзыв токенов, графики использования, недавние сессии, "Agent inference key" |
| `/auth/login`, `/auth/callback`, `/auth/logout` | браузер | PKCE OIDC; нужна роль `ai-user` или `ai-admin` |
| `/api/tokens` (GET, POST), `/api/tokens/{id}` (POST = отзыв) | дашборд | CRUD токенов; имя 1-100 символов, срок 1-365 дней, по умолчанию 90 |
| `/api/agent-token` (POST) | дашборд | выпуск ключа агента пользователя |
| `/api/usage/daily`, `/api/usage/sessions`, `/api/usage/limit` | дашборд | использование из `qos_events` |
| `/v1/*` (публичный) | программы, агенты, Automations Open WebUI | прокси PAT -> JWT в AI Gateway |
| `/mcp/<name>/` (только внутри кластера) | агенты, вызовы инструментов из Open WebUI | MCP-прокси |
| `/healthz` | kubelet | ping базы данных |
| `:9090/metrics` (только внутри кластера) | Prometheus | метрики `patsvc_*` |

## Жизненный цикл токена

- **Выпуск.** На `/platform`. Полный токен показывается один раз; в базе
  хранятся только HMAC-хэш, 15-символьный префикс для отображения, владелец,
  имя, срок и `issued_by` (`user` или `agents`).
- **Использование.** `Authorization: Bearer sk-...` на `https://<origin>/v1`.
  Несколько токенов одного пользователя делят его лимиты: лимиты считаются
  по владельцу, а не по токену.
- **Отзыв.** На `/platform`; действует со следующего запроса. Отозванные
  строки остаются в таблице с заполненным `revoked_at`.
- **Истечение.** В момент `expires_at`. Ключи агентов истекают через
  `AGENT_PAT_TTL_DAYS` (7); выпуск нового отзывает предыдущий ключ агента.
- **Смена `PAT_HASH_KEY` делает недействительными все сохранённые токены.**
  Относитесь к ней как к массовому отзыву.

Оператор может выпустить токен за пользователя из командной строки через
`scripts/kc-pat-issue` (см. [scripts/README.md](../../scripts/README.md)).

## Склейка сессий

Агенты и coding-инструменты на каждом шаге пересылают весь разговор. Для
`/v1/chat/completions` pat-service хэширует разговор цепочкой
([ADR 0011](../adr/0011-pat-session-key-langfuse-tracing.md),
`internal/qos/chain.go`):

```
c0 = SHA256(model | tools | message[0])
ci = SHA256(c(i-1) | message[i])
```

Каждое звено хранится в Valkey (`qos:chain:<sub>:<link>`, TTL
`QOS_SESSION_TTL_SECONDS`, 1800 с). Новый запрос ищет свои звенья, начиная с
самого нового: если какое-то известно, запрос принадлежит той сессии; если
нет, выдаётся новый `sess-<24 hex>`. Ключ уходит дальше как `X-Session-Key`,
и AI Gateway отображает его в `session.id` Langfuse, так что один запуск
агента - одна сессия в Langfuse. `Agent-Session-Id` от клиента срезается,
чтобы он не мог подменить ключ, вычисленный сервером.

Следствия:

- У двух пользователей никогда не бывает общей сессии: `sub` владельца входит в ключ.
- Разговор, простоявший дольше TTL, начинает новую сессию.
- Хэшируются только тела до `QOS_FINGERPRINT_MAX_BODY_BYTES` (4 MiB); на
  поиск отведено `QOS_FINGERPRINT_TIMEOUT_MS` (200 мс). Любая ошибка
  приводит к "нет сессии", но никогда не к упавшему запросу.
- `patsvc_session_match_total{result}` показывает, как часто запросы совпадают.

## Выбор полосы приоритета

`assignBand` в `internal/qos/session.go` выбирает для запроса одну из трёх
полос EPP; полная модель очереди - в
[очередях и fair share](inference/queues-and-fair-share.ru.md).

| Полоса | Когда | Приоритет |
| --- | --- | --- |
| `demoted` | владелец отправил больше `QOS_DEMOTE_AFTER_STEPS` (8) запросов подряд в одной сессии (серия сбрасывается при смене сессии), или недавний расход владельца превышает наименьший расход среди других активных пользователей больше чем на `QOS_SPEND_DEMOTE_THRESHOLD` (5.0 единиц стоимости за `QOS_SPEND_WINDOW_SECONDS`, 600 с) | 1 |
| `warm` | сессию отправляли в движок в последние `QOS_WARM_TTL_SECONDS` (120 с), так что её KV-кэш, скорее всего, ещё в памяти | 10 |
| `normal` | всё остальное, а также любая ошибка Valkey | 5 |

Понижение проверяется первым. Полоса уходит как
`X-Llm-D-Inference-Objective`, `sub` владельца - как
`X-Llm-D-Inference-Fairness-Id`.

## Учёт использования и стоимости

Два разных числа для двух целей:

| | Единицы стоимости для планирования | Деньги |
| --- | --- | --- |
| Формула | `QOS_COST_ALPHA_PER_TOKEN` x некэшированные токены промпта + `QOS_COST_BETA_PER_TOKEN` x токены ответа | цены за 1K из `QOS_PRICING_FILE` (ConfigMap `pat-service-pricing`): промпт, кэшированный промпт, ответ |
| Используется | понижение по расходу (Valkey `qos:spend:<sub>`) | дашборд, `qos_events.cost_amount` |
| Метрика | `patsvc_cost_units_total` | - |

Использование берётся из ответа: для стримов pat-service добавляет
`stream_options.include_usage` и читает финальный чанк с usage. Эмбеддинги
учитываются (`patsvc_embedding_tokens_total`, `qos_events` с полосой
`embeddings`), но на полосы не влияют.

## Какое состояние хранит

| Хранилище | Содержимое | Срок жизни |
| --- | --- | --- |
| Postgres `pat-db` (CNPG), таблица `personal_access_tokens` | хэш токена, префикс, владелец, имя, даты, `issued_by` | навсегда; отозванные строки остаются |
| там же, таблица `qos_events` | строка на каждый ответ чата или эмбеддингов: владелец, сессия, модель, полоса, токены, стоимость, id токена | навсегда (задачи очистки нет) |
| Valkey `envoy-ratelimit-valkey` | цепочки сессий, серии, времена отправки, расход, активные пользователи, окна rate limit для MCP | TTL от 2 до 30 минут |
| Secret Kubernetes `agents/agent-cred-<id>` | текущий ключ агента пользователя | до перевыпуска или удаления профиля |

Картина по всему стеку - в [данных и сроках хранения](observability/data-and-retention.ru.md).

## Типовые сбои

| Симптом | Вероятная причина | Проверка / исправление |
| --- | --- | --- |
| Все PAT разом падают с 401 | закэшированный JWT pat-service для шлюза истёк раньше срока | лог Envoy шлюза `Jwt_is_expired`; `kubectl -n airgap-ai-stack rollout restart deploy/pat-service`; сравнить срок жизни access token клиента `pat-gateway` в Keycloak с файлом realm |
| Один токен получает 401 | отозван, истёк или сменился `PAT_HASH_KEY` | состояние токена видно на дашборде |
| 503 на `/v1` или `/mcp` | база недоступна | `kubectl -n airgap-ai-stack get cluster pat-db` |
| Нет сессий в Langfuse для PAT-трафика | Valkey недоступен (сервис работает дальше без сессий) или потерян маппинг заголовка в AI Gateway | `patsvc_session_match_total`; `config/ai-gateway/values.yaml` |
| Кнопка ключа агента не работает | RBAC pat-service в namespace `agents` | `kubectl -n agents get role pat-service-agent-key` |

## Где это лежит

- Код: `pat-service/cmd/pat-service/` (`main.go` - маршруты и конфигурация,
  `mcp.go`, `agents.go`, `usage.go`), `pat-service/internal/qos/`,
  дашборд `pat-service/web/`
- Deployment и env: `k8s/base/applications.yaml` (рендерится в
  `helm/airgap-stack`); образ `PAT_SERVICE_IMAGE` в `versions.lock.env`,
  собирается CI (`.github/workflows/pat-service-image.yml`)
- Клиенты Keycloak `pat-dashboard`, `pat-gateway`: `make provision-pat-oidc`
- Тесты: `cd pat-service && go test ./...`; smoke границы: `make pat-smoke`
