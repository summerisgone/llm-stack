# Open WebUI

[Русский](openwebui.ru.md) | [Handbook index](README.md)

Open WebUI is the browser face of the stack. People sign in with Keycloak, pick
a model or one of their personal agents, and chat; they can switch on MCP
tools per chat. It holds no model and no token store of its own that matters:
inference goes to the private AI Gateway with the user's own Keycloak token.

## What users get

| In the model picker | What it is | Goes through |
| --- | --- | --- |
| `qwen-3.8-27b` | the model itself, whichever engine serves it | private AI Gateway -> EPP -> engine |
| `automations.*` | the same catalogue, for Automations (scheduled runs) | pat-service `/v1` with a shared PAT |
| `Hermes agent (personal)`, `Pi agent (personal)`, `OpenCode agent (personal)` | the user's own agent, one per runtime | agent-broker -> the user's agent pod |

Also available to every user (`USER_PERMISSIONS_*` in the Deployment):
workspace models, knowledge, prompts, tools and skills; Open WebUI's own API
keys; Automations. The MCP tools `web-search` and `repowise` appear in the
chat's tool menu when enabled on the site ([MCP](mcp/README.md)); they are off
per chat until the user turns them on.

Not configured: Open WebUI's built-in web search (`ENABLE_WEB_SEARCH=false`;
search is the MCP tool instead), its RAG/embedding settings (Open WebUI
defaults; the stack's bge-m3 is not wired into it), image generation and
audio.

## How it is wired

```
browser --SSO--> Open WebUI --(user's Keycloak token)--> ai-gateway-private -> EPP -> engine
                     |--(shared automations PAT)------> pat-service /v1
                     |--(user's Keycloak token)-------> agent-broker (agents namespace)
                     \--(user's Keycloak token)-------> pat-service /mcp/<name>/   (tools)
```

- `auth_type: system_oauth` means Open WebUI attaches the signed-in user's
  Keycloak access token to the request. The gateway, the broker and
  pat-service each validate it; none trusts Open WebUI's own word.
- `ENABLE_FORWARD_USER_INFO_HEADERS=true` adds `X-User-Name` / `X-User-Id`
  and, for agents, `X-OpenWebUI-Chat-Id`, which keeps one agent session per
  chat.
- `TASK_MODEL_EXTERNAL=qwen-3.8-27b`: chat titles, tags and follow-ups are
  generated by the model, never by an agent (each would be a full agent turn).
- Open WebUI traffic does not pass through pat-service, so it carries no
  priority band: EPP puts it in the fallback band `0`, the lowest
  ([queues](inference/queues-and-fair-share.md)). Its traces in Langfuse
  have a user but no session key.

## Model connections

`OPENAI_API_BASE_URLS` and `OPENAI_API_CONFIGS` in
`k8s/overlays/remote-wsl-vllm-nvfp4/openwebui-oidc-patch.yaml` declare three
connections by index:

| Index | Base URL | Auth | Models | Why |
| --- | --- | --- | --- | --- |
| `0` | `ai-gateway-private...:8080/v1` | `system_oauth` | `qwen-3.8-27b` (declared) | chat; the gateway has no model catalogue Open WebUI can discover |
| `1` | `pat-service...:8080/v1` | `bearer` `OPENWEBUI_AUTOMATIONS_PAT` | discovered, prefix `automations` | Automations run with no browser session, so they need a static credential |
| `2` | `agent-broker.agents...:8080/v1` | `system_oauth` | `hermes-agent`, `pi-agent`, `opencode-agent` (declared) | personal agents; the broker lists models only for a user token |

`ENABLE_PERSISTENT_CONFIG=false`: settings changed in the admin UI live only
until the pod restarts. Anything that must persist is an env var in the
manifests. A new model name or agent runtime is an edit of `model_ids`
there, then `make helm-up`.

MCP tool servers come from the ConfigMap `openwebui-tool-servers` (key
`TOOL_SERVER_CONNECTIONS`), rendered by `helm/airgap-stack` from
`openwebuiToolServers` in its values and read at start only. See
[MCP](mcp/README.md#open-webui).

## Sign-in and roles

- Sign-in is Keycloak only: `ENABLE_LOGIN_FORM=false`,
  `ENABLE_PASSWORD_AUTH=false`, `ENABLE_SIGNUP=false`, accounts are created
  on first OIDC login (`ENABLE_OAUTH_SIGNUP=true`).
- Roles come from the token (`OAUTH_ROLES_CLAIM=realm_access.roles`,
  `ENABLE_OAUTH_ROLE_MANAGEMENT=true`): `ai-user` is a regular user,
  `ai-admin` is an Open WebUI admin, any other account is refused
  (`OAUTH_ALLOWED_ROLES=ai-user,ai-admin`). A role change applies at the
  next login.
- An init container (`sso-role-bootstrap`) seeds a placeholder user so the
  first real SSO user is not promoted to admin automatically.
- `OAUTH_SCOPES` includes `offline_access`, applied to the Keycloak client
  by `scripts/provision-openwebui-offline-access` (run by `make helm-up`).
  It keeps the stored refresh token alive past Keycloak's SSO idle timeout;
  without it, idle users lose inference with a silent 401.

User accounts themselves are managed in Keycloak; see
[operations](operations.md#users-and-access).

## What to expect

- **The model name never changes.** `qwen-3.8-27b` is served by whichever
  engine is live; an engine switch is invisible to users apart from the
  downtime of the switch itself ([engines](engines/README.md)).
- **First message to an agent** is answered by the broker, not the agent:
  an onboarding text, and the profile is created. The agent pod starts on
  demand on the next message, after a cold start the broker logs as
  `"agent started"`; when all slots are busy the user sees a queue notice
  ([agents](agents/README.md)).
- **An agent needs an agent key.** Until the user presses "Issue agent key"
  on `/platform`, agent turns fail with a 401 from the model.
- **Limits:** 60 requests per minute per user on the model route (HTTP 429
  above it) and 30 MCP tool calls per minute per user and server
  ([tuning](configuration/tuning.md#rate-limits)).
- **With `INFERENCE_ENGINE=ninfer`,** JSON-mode `response_format` is refused
  by the engine; features that rely on it (some title or tool helpers)
  degrade.
- **Chats are stored** in Open WebUI's SQLite on its PVC, and every prompt and
  answer is also traced to Langfuse
  ([data and retention](observability/data-and-retention.md)).

## Operating it

| Symptom | Check | Fix |
| --- | --- | --- |
| One user gets 401 from the model, others do not | Open WebUI log `No OAuth session found for user`; gateway log `Jwt_is_missing` | the user logs out and back in (new OIDC callback) |
| Tool server missing in the chat menu | ConfigMap `openwebui-tool-servers` exists and has the entry; the flag in `.env` | `make helm-up`, then `kubectl -n airgap-ai-stack rollout restart deploy/openwebui` |
| Agent model returns 404 | the broker's `PI_IMAGE` / `OPENCODE_IMAGE` is set | [agents](agents/managing.md) |
| Admin UI change lost after restart | `ENABLE_PERSISTENT_CONFIG=false` is intended | put the setting in the manifest |

```sh
kubectl -n airgap-ai-stack logs deploy/openwebui --tail=100
kubectl -n airgap-ai-stack get configmap openwebui-tool-servers -o jsonpath='{.data.TOOL_SERVER_CONNECTIONS}'
```

## Where it lives

- Deployment, env and PVC `openwebui-data` (SQLite `webui.db`):
  `k8s/base/applications.yaml`
- Site patches (connections, OIDC redirect, web-search toggle):
  `k8s/overlays/remote-wsl-vllm-nvfp4/openwebui-oidc-patch.yaml`,
  `openwebui-web-search-patch.yaml`
- Tool servers: `helm/airgap-stack/values.yaml` `openwebuiToolServers`,
  `helm/airgap-stack/templates/openwebui-tool-servers.yaml`
- Applied by `make helm-up`; image pinned in `versions.lock.env`
- Operator API notes: `.claude/skills/openwebui-api/SKILL.md`
